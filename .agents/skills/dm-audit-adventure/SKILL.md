# Audit an adventure

1. Always read the root `AGENTS.md`, `docs/adventure-audit-guide.md`, and `docs/validierung.md`. Follow the audit guide's scope, read order, severity definitions, finding format, report order, and read-only boundary. Do not load every normative guide up front.
2. Load additional references only for the affected audit area: `docs/asset-katalog.md` for type or canonical-path questions; the relevant type section of `docs/asset-authoring-guide.md` for table readiness; `docs/adventure-structure-guide.md` for player agency, information paths, plot threads, resolutions, pacing, or safe cuts; `docs/metadaten-und-werte.md` for metadata or controlled values; `docs/beziehungen-und-speicherorte.md` for ownership, movement, reciprocity, or continuity; `docs/player-handout-workflow.md` when a scoped Handout has a `player.md` or player-facing Visual; and `docs/bild-workflow.md` when a scoped Visual, prompt, or PNG exists.
3. Read `adventure/README.md`, `adventure/50-indexes/clue-matrix.md`, `adventure/60-session/dm-cheat-sheet.md`, `adventure/60-session/run-sheet.md`, `adventure/60-session/readiness-report.md`, the six asset indexes, and `adventure/90-meta/open-questions.md`, `assumptions.md`, and `decisions.md`. Derive the narrow set of active plot threads, necessary conclusions, locations, and directly linked assets to inspect. Use the clue matrix only to select paths for inspection; verify truth, truth status, presentation, and consequences in every linked canonical Information and source asset. Record whether every central asset is reachable directly from the README or through exactly one matching index without full-text search or blind directory scanning.
4. Run:

   ```bash
   python3 scripts/validate_adventure.py
   ```

5. Keep technical diagnostics separate. Treat validator errors as blocking technical results; review warnings in context rather than automatically promoting them to findings.
6. Apply the guide's sequence: canon and continuity; global clue-matrix coverage and canonical necessary information paths; player outputs and relevant Visuals; every active plot thread; complete one-shot resolution paths; qualitative pacing and safe cuts; README, DM cheat sheet, Session Run Sheet, and index navigation; and table readiness. Check that every necessary conclusion has at least two genuinely independent, concretely presentable paths and that repeated wording is not mistaken for source or access independence. Check the target frame, minimum resolution state, prose content roles, each declared safe cut, and `late pressure` without calculating missing runtime or inventing a Scene order. Verify that the Run Sheet carries only optional preflight times and source-backed flexible phases, checkpoints, pressure, cuts, finale triggers, openings, and endings. Verify that README, clue matrix, DM cheat sheet, Run Sheet, and index contexts are short, current, action-relevant, and linked to the only canonical source rather than duplicating it. Confirm that central NPCs have immediate intent and a source-backed Voice cue, critical conclusions show independent fallback paths, and cuts preserve the minimum resolution. Compare each scoped `player.md` with its Handout, `reveals`, truth boundaries, and delivery context. Compare each relevant Visual and prompt with its Subject identity, depicted One-Shot state, visibility, exclusions, and any existing PNG. If the PNG cannot be inspected visually with available tools, report that limit instead of treating it as verified. For contradictions, inspect every file that asserts the affected canon. Do not infer one correct version when the sources are ambiguous.
7. Record each narrative finding as `blocking`, `important`, or `polish` with area, affected canon, rationale, every evidence path, impact, and smallest useful correction direction.
8. Report in the guide's order, including clue-matrix coverage for every necessary conclusion, every active plot thread, each scoped `player.md`, each relevant Visual, every declared safe cut, the DM cheat sheet, the Session Run Sheet, all six asset indexes, the navigation path to every central asset, and whether the existing readiness status agrees with preflight, validator, audit findings, and blockers. If no finding exists, say so explicitly. Do not update the readiness report without an explicit write request and never copy findings into it.
9. Do not modify any file unless the user explicitly requests fixes. For a fix request, name selected finding IDs and affected files first, make the smallest coherent edits, update required indexes and change log, then rerun technical and affected narrative checks.

Do not create system mechanics, fill missing story content, or judge literary quality during an audit.
